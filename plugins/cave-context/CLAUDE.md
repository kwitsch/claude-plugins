# CLAUDE.md — cave-context

One MCP server that proxies the context-mode MCP server (minus a small denylist of tools) and hosts aggregated caveman+context-mode hook handlers. Replaces both plugins.

## Behavior
- **Runtime launcher** `bin/bnx.sh` (chmod +x) owns runtime selection — every `.mjs` (server + command hooks) and the upstream `context-mode` package launch through it. It prepends `${HOME}/.local/bin` + `${HOME}/.bun/bin` to PATH (use `${HOME}`, never `~`), detects bun via `command -v bun`, and dispatches on the first arg: a `*.mjs` → `bun <script>` (else `node <script>`); an npm package → `bun x <pkg>` (else `npx -y <pkg>`). No arg → stderr + exit 64. `.mcp.json` + the SessionStart command hook in `hooks.json` use exec form `command: bin/bnx.sh`, `args: [<.mjs or pkg>]`.
- `mcp/server.mjs`: launches `context-mode` upstream (via `bnx.sh`, default `proxy.mjs` cmd resolved with `import.meta.url`), re-exposes its `ctx_*` tools, also serves `hook_*` tools. The upstream context-mode is spawned with `CONTEXT_MODE_DIR` = `${CLAUDE_PLUGIN_DATA}/context-mode` (its persistent storage root — survives plugin updates; context-mode keeps `sessions/` + `content/` under it), set via the shared `mcp/context-mode-env.mjs` helper (only when `CLAUDE_PLUGIN_DATA` is non-empty; an explicit pre-existing `CONTEXT_MODE_DIR` wins). The same helper is applied to the delegate CLI spawn (`mcp/delegate.mjs`), so the hook-captured data and the MCP server share one storage root (no split-brain). A `DENIED_UPSTREAM_TOOLS` set (`ctx_stats`, `ctx_doctor`, `ctx_upgrade`) is the single choke point for tool removal: stripped from `tools/list` and rejected on `tools/call` (-32602 `unknown tool`, before the upstream-liveness check, so the verdict is deterministic and they never reach `up.callTool`). `proxy.mjs` stays a faithful 1-to-1 transport — the denylist policy lives in the server, not the proxy. **No in-file bun re-exec shim** — `bnx.sh` owns runtime selection; the module just calls `startServer()`.
- `hooks/hooks.json` (handler-type rationale follows `.claude/rules/hooks-mcp-server.md` + the event matrix — each command hook is justified by a *specific* reason, not a blanket "early-lifecycle" claim): SessionStart = `command` hook (`hooks/sessionresume.mjs` via `bnx.sh`) **matched `resume|compact`** (SessionStart matchers filter on the session source, so the hook fires only on resume/compact) — `command` is **pre-connect**: the MCP server is not up on first run, so `mcp_tool` would fail open; it does **not** emit the caveman ruleset — it only **delegates** to context-mode's `sessionstart` CLI route to restore prior-session continuity on resume/compact — context-mode's routing block is **stripped** from the upstream response (`extractContinuity` whitelists only the `<session_knowledge …>` / `# Session Resume` continuity markers), so double-injection is prevented. The matcher excludes `startup`/`clear`, so a **second SessionStart `command` hook** `hooks/sessionstartup.mjs` (via `bnx.sh`) **matched `startup`** delegates the fresh-start envelope to the same CLI route PURELY for context-mode's startup-only side-effects (CLAUDE.md-capture, old-session GC, the `session_start` lifecycle anchor) — it injects no continuity and **always emits `{}`** (context-mode's routing block is discarded, never surfaced), preserving parity with context-mode's session model. (Mid-session capture via PostToolUse/UserPromptSubmit/PreCompact is independent of SessionStart regardless — context-mode's capture path `ensureSession`s with `INSERT OR IGNORE`.) `clear` triggers neither delegating hook (a no-op upstream). On resume/compact the hook emits a `hookSpecificOutput` envelope whose `additionalContext` carries the restored continuity payload; with no continuity it omits the envelope and emits `{}` (never `additionalContext: null`, which fails Claude Code's output-schema validation). Continuity restore depends on the context-mode CLI responding within the bounded delegation timeout (default 5s, `CAVE_CONTEXT_SESSIONSTART_TIMEOUT_MS`); on cold upstream spawn the hook fails open to no continuity (emits `{}`), so resume-continuity is best-effort. Fail-open: a slow/absent/erroring context-mode CLI still yields valid output — `{}` (continuity is null in-process, never surfaced as a present `additionalContext: null`); the in-code `input.source === "clear"` guard remains as defense-in-depth (the matcher already excludes `clear`). A **third SessionStart `command` hook** `cat`s `hooks/SessionStart.md` (exec-form `cat`, no matcher so it fires on every source) — the **sole source** of the caveman ruleset: a static doc holding the caveman ruleset plus a cave-context-adapted version of context-mode's routing rules (bare `ctx_*` names; WebFetch hard-denied → `ctx_fetch_and_index`). PreCompact = `mcp_tool` → `hook_precompact` (mid-session, server connected) — delegates context-mode's pre-context-loss resume snapshot; **best-effort**: fails open if the server is momentarily down at compact time (no `precompact.mjs` command-hook shim; `bnx.sh` is no longer involved). UserPromptSubmit + PreToolUse + PostToolUse = `mcp_tool` → `hook_*` — mid-session, non-blocking, server connected. UserPromptSubmit is `limited` in the matrix (per-prompt 30 s round-trip), so it was a deliberate choice over a command hook: drops the per-prompt `node` spawn + the extra shim file, at the cost of a per-prompt MCP round-trip and a first-prompt server-connect race (reminder/prompt-capture may be dropped on turn 1 — low impact, SessionStart already injected the fresh ruleset that turn). No ConfigChange hook — the `caveman_level` userConfig it reacted to was removed (level is fixed at full, nothing to re-seed live). No Stop hook — subagent tracking was removed; a no-op Stop hook adds an MCP round-trip per stop event with no benefit.
- caveman reimplemented in `mcp/caveman.mjs` — **fixed at level `full`**: no level switching (lite/ultra removed), no off switch, no userConfig, no runtime state. The module is just one text builder — `reminderText()` (per-turn UserPromptSubmit reminder), hardcoded to full. The SessionStart ruleset + routing is now the static `hooks/SessionStart.md` (sole source — no dynamic builder). **All events including SessionStart are delegated** — SessionStart delegates to context-mode via `delegateHook("SessionStart", …)` to run DB session-init side-effects and return any continuity payload; double-injection is prevented by stripping context-mode's routing block via `extractContinuity` (whitelists only `<session_knowledge …>` / `# Session Resume` markers). The five delegated event keys (`sessionstart`/`pretooluse`/`posttooluse`/`precompact`/`userpromptsubmit`) are dispatched via `bnx.sh context-mode hook claude-code <event>` (default `delegate.mjs` cmd resolved with `import.meta.url`). The delegate CLI spawn also receives `CONTEXT_MODE_DIR` = `${CLAUDE_PLUGIN_DATA}/context-mode` (via the shared `mcp/context-mode-env.mjs` helper), so hook-captured data shares the same persistent storage root as the upstream MCP server (no split-brain). Platform token `claude-code` and the **lowercase** delegated event keys are verified against context-mode 1.0.162 `cli.bundle.mjs` routing map. The CLI `process.exit(1)`s silently on an unknown platform/event key, so `delegate.mjs` lowercases the event before invoking it.
- **WebFetch redirect**: `handlePreToolUse` hard-redirects `WebFetch` for the main agent only (`!agent_id`) — returns `permissionDecision: "deny"` with a `ctx_fetch_and_index` hint. This is a soft JSON block (the `mcp_tool` hook fails open if the server is down, consistent since `ctx_fetch_and_index` would be unavailable then too). Subagent WebFetch (`agent_id` present) falls through to the context-mode delegate, which independently governs it.
- Reentrancy: PreToolUse/PostToolUse matchers must never match `hook_` tools.

## Skills
- `skills/cave-compress/SKILL.md` — **model- and user-invocable** Markdown compressor (no `disable-model-invocation`; `description` + `when_to_use` carry path hints so the model knows when to apply it). Rewrites ONE `.md` file in place under the caveman ruleset (ported from `JuliusBrussee/cavekit`; the runtime prose ruleset in `mcp/caveman.mjs` is **not** reused — different surface). Model-driven, no binary. Two fail-closed gates run before the lossy overwrite regardless of who invoked it: a **recoverability gate** (target must be git tracked+clean, else `AskUserQuestion`; gitignored files are told "no restore point", never "commit first") and a **scope gate** (auto-allows `**/CLAUDE.md`, `docs/**/*.md`, `plan/**/*.md` relative to the repo root; any other `.md` needs explicit confirmation). PRESERVE-VERBATIM (code/paths/URLs/numbers/frontmatter) and Markdown structure are hard rules; SHAPES apply only when the file already uses them. Not bats-tested beyond presence/frontmatter — model-driven body is verified by the dev-time self-test.
