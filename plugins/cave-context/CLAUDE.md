# CLAUDE.md — cave-context

One MCP server that runs context-mode in-process (minus a small denylist of tools) and hosts aggregated caveman+context-mode hook handlers. Replaces both plugins.

## Runtime + vendoring

context-mode v1.0.162 (ELv2, © 2026 Mert Koseoglu) is vendored at `bin/context-mode/`. Requires **Node ≥ 22.5** with FTS5-capable `node:sqlite` — the vendored copy is pure-JS (no `better-sqlite3` binary). On a non-FTS5 node, hooks fail open: emit `{}` with a stderr diagnostic.

### Re-vendor context-mode

To update the vendored subtree to a new version:

1. `npm pack context-mode@<ver>` — produces a tarball.
2. Extract into `plugins/cave-context/bin/context-mode/` (replacing existing contents).
3. Strip the foreign-platform hook dirs: `gemini-cli/`, `cursor/`, `vscode-copilot/`, `codex/`, `kimi/`, `kiro/`, `jetbrains-copilot/`.
4. Strip packaging metadata: `.claude-plugin/`, `.codex-plugin/`, `.openclaw-plugin/`, `openclaw.plugin.json`, `skills/`, `hooks/hooks.json`.
5. Verify the tarball sha256 matches the expected value.
6. Update `bin/context-mode/NOTICE` with the list of removed dirs/files.
7. Bump `plugin.json` version (minor if behavior-bearing).

## Behavior
- **Runtime** — the `.mjs` are invoked directly: `.mcp.json` `command` = `${CLAUDE_PLUGIN_ROOT}/mcp/server.mjs`; the two SessionStart `command` hooks = `hooks/sessionresume.mjs` / `hooks/sessionstartup.mjs` (each `#!/usr/bin/env node`, `100755`). No launcher wrapper — cave-context is node-only; context-mode is vendored and run in-process, so no runtime selection or npm-package launch is needed. Node is assumed on the spawn PATH. Note: this direct-`.mjs` invocation is a deliberate deviation from the repo's `bin/mjs-launch.sh` wrapper canonical (per an explicit "always node" user instruction); it loses the wrapper's `${HOME}/.local/bin` PATH prepend (node assumed on the spawn PATH).
- `mcp/server.mjs`: serves `ctx_*` tools via the in-process `mcp/embed.mjs` adapter (imports the vendored `bin/context-mode/server.bundle.mjs` with `CONTEXT_MODE_EMBEDDED_PLUGIN_TOOLS=1`; no child-spawn), also serves `hook_*` tools. `CONTEXT_MODE_DIR` is set to `${CLAUDE_PLUGIN_DATA}/context-mode` (its persistent storage root — survives plugin updates; context-mode keeps `sessions/` + `content/` under it), via the shared `mcp/context-mode-env.mjs` helper (only when `CLAUDE_PLUGIN_DATA` is non-empty; an explicit pre-existing `CONTEXT_MODE_DIR` wins). The helper is also applied to the embedded import (`embed.mjs`) and to the SessionStart spawn (`sessionstart-spawn.mjs`), so all paths share one storage root (no split-brain). A `DENIED_UPSTREAM_TOOLS` set (`ctx_stats`, `ctx_doctor`, `ctx_upgrade`) is the single choke point for tool removal: stripped from `tools/list` and rejected on `tools/call` (-32602 `unknown tool`, before the upstream-liveness check, so the verdict is deterministic and they never reach `up.callTool`). `embed.mjs` is a faithful adapter — the denylist policy lives in the server, not the adapter. the module just calls `startServer()`; no re-exec shim and no wrapper (invoked directly via its shebang).
- `hooks/hooks.json` (handler-type rationale follows `.claude/rules/hooks-mcp-server.md` + the event matrix — each command hook is justified by a *specific* reason, not a blanket "early-lifecycle" claim): SessionStart = `command` hook (`hooks/sessionresume.mjs`, invoked directly) **matched `resume|compact`** (SessionStart matchers filter on the session source, so the hook fires only on resume/compact) — `command` is **pre-connect**: the MCP server is not up on first run, so `mcp_tool` would fail open; it does **not** emit the caveman ruleset — it spawns the vendored `node bin/context-mode/hooks/sessionstart.mjs` via `mcp/sessionstart-spawn.mjs` (test override `CAVE_CONTEXT_SESSIONSTART_SCRIPT`) to restore prior-session continuity on resume/compact — context-mode's routing block is **stripped** from the response (`extractContinuity` whitelists only the `<session_knowledge …>` / `# Session Resume` continuity markers), so double-injection is prevented. The matcher excludes `startup`/`clear`, so a **second SessionStart `command` hook** `hooks/sessionstartup.mjs` (invoked directly) **matched `startup`** spawns the same vendored `sessionstart.mjs` PURELY for context-mode's startup-only side-effects (CLAUDE.md-capture, old-session GC, the `session_start` lifecycle anchor) — it injects no continuity and **always emits `{}`** (context-mode's routing block is discarded, never surfaced), preserving parity with context-mode's session model. (Mid-session capture via PostToolUse/UserPromptSubmit/PreCompact is independent of SessionStart regardless — context-mode's capture path `ensureSession`s with `INSERT OR IGNORE`.) `clear` triggers neither hook (a no-op upstream). On resume/compact the hook emits a `hookSpecificOutput` envelope whose `additionalContext` carries the restored continuity payload; with no continuity it omits the envelope and emits `{}` (never `additionalContext: null`, which fails Claude Code's output-schema validation). Continuity restore depends on the vendored `sessionstart.mjs` responding within the bounded spawn timeout (default 5s, `CAVE_CONTEXT_SESSIONSTART_TIMEOUT_MS`); on slow/absent spawn the hook fails open to no continuity (emits `{}`), so resume-continuity is best-effort. The in-code `input.source === "clear"` guard remains as defense-in-depth (the matcher already excludes `clear`). A **third SessionStart `command` hook** `cat`s `hooks/SessionStart.md` (exec-form `cat`, no matcher so it fires on every source) — the **sole source** of the caveman ruleset: a static doc holding the caveman ruleset plus a cave-context-adapted version of context-mode's routing rules (bare `ctx_*` names; WebFetch hard-denied → `ctx_fetch_and_index`). PreCompact = `mcp_tool` → `hook_precompact` (mid-session, server connected) — delegates context-mode's pre-context-loss resume snapshot; **best-effort**: fails open if the server is momentarily down at compact time. UserPromptSubmit + PreToolUse + PostToolUse = `mcp_tool` → `hook_*` — mid-session, non-blocking, server connected. UserPromptSubmit is `limited` in the matrix (per-prompt 30 s round-trip), so it was a deliberate choice over a command hook: drops the per-prompt `node` spawn + the extra shim file, at the cost of a per-prompt MCP round-trip and a first-prompt server-connect race (reminder/prompt-capture may be dropped on turn 1 — low impact, SessionStart already injected the fresh ruleset that turn). No ConfigChange hook — the `caveman_level` userConfig it reacted to was removed (level is fixed at full, nothing to re-seed live). No Stop hook — subagent tracking was removed; a no-op Stop hook adds an MCP round-trip per stop event with no benefit.
- caveman reimplemented in `mcp/caveman.mjs` — **fixed at level `full`**: no level switching (lite/ultra removed), no off switch, no userConfig, no runtime state. The module is just one text builder — `reminderText()` (per-turn UserPromptSubmit reminder), hardcoded to full. The SessionStart ruleset + routing is the static `hooks/SessionStart.md` (sole source — no dynamic builder). The 4 mid-session hook events (PostToolUse/UserPromptSubmit/PreToolUse/PreCompact) run **in-process** via `mcp/inproc-hooks.mjs` (calls the vendored work functions — extractEvents/attributeAndInsertEvents/SessionDB/ROUTING_BLOCK/buildResumeSnapshot); `mcp/delegate.mjs` routes them. No per-event CLI spawn. SessionStart spawns the vendored `bin/context-mode/hooks/sessionstart.mjs` via `mcp/sessionstart-spawn.mjs` (not via a CLI delegate).
- **WebFetch redirect**: `handlePreToolUse` hard-redirects `WebFetch` for the main agent only (`!agent_id`) — returns `permissionDecision: "deny"` with a `ctx_fetch_and_index` hint. This is a soft JSON block (the `mcp_tool` hook fails open if the server is down, consistent since `ctx_fetch_and_index` would be unavailable then too). Subagent WebFetch (`agent_id` present) falls through to the context-mode delegate, which independently governs it.
- Reentrancy: PreToolUse/PostToolUse matchers must never match `hook_` tools.
- **`compress` tool** (`mcp/compress.mjs`): a first-class MCP tool (real `inputSchema`, distinct from the permissive `hook_*` tools and proxied `ctx_*` tools) — `{ text }` in, `{ compressed, changed, valid, errors, reason? }` out. Ported from upstream caveman-compress (`compress.py` + `validate.py`): split frontmatter (preserved verbatim) → compress body via `callClaude` → `stripLlmWrapper` → reassemble → `validate` (URLs, fenced code blocks, headings) → ≤2 (`MAX_RETRIES`) cherry-pick-fix retries; refuses empty input and input > `MAX_INPUT_BYTES` (500 000). `callClaude` spawns `claude --print --output-format text --strict-mcp-config --no-session-persistence --setting-sources project` with `cwd=os.tmpdir()` — isolation prevents the cave-context server from re-spawning (no recursion) and stops user plugins/hooks loading. Zero-dependency (`node:child_process`, no Anthropic SDK; `claude --print` covers both desktop auth and `ANTHROPIC_API_KEY`). Env knobs: `CAVE_COMPRESS_CLAUDE_BIN`, `CAVE_COMPRESS_MODEL`, `CAVE_COMPRESS_TIMEOUT_MS`. Registered via `LOCAL_TOOLS` in `server.mjs` and `HANDLERS.compress` (`handleCompress`) in `handlers.mjs`. `mcp/compress.mjs` is imported (not spawned) so it needs no executable bit.
- **Branch-change auto-reindex** (`mcp/branch-index.mjs`, imported — not spawned, so no executable bit): on every `PostToolUse`, `server.mjs` fires `branchIndexer.note(input.cwd)` **fire-and-forget** (never awaited — the hook response is unaffected). The tracker resolves the git branch + repo root for `cwd` via one `git -C <cwd> rev-parse --show-toplevel HEAD --abbrev-ref HEAD` spawn (slash branch names kept whole; detached HEAD → short SHA). When the branch differs from the last successfully-indexed branch for that root — the first observation per server process counts as a change ("startup = change", since state is in-memory) — it calls the upstream `ctx_index` (`path`=repo root, `source`=`project:<basename>`, `maxDepth:5`, `maxFiles:200`, identical to `init-branch`). It only proceeds once the upstream has started (`ensureUp()`); if the upstream is down it skips and retries on the next `PostToolUse` (the branch is committed to state ONLY on a successful index). Single-flight: `inflightCwds` (cheap pre-await, same cwd) + `inflightRoots` (authoritative per repo root) prevent concurrent/duplicate indexes. The internal `ctx_index` is dispatched in-process via `embed.mjs`, so it triggers **no** PostToolUse reentrancy. Gated by the `branch_reindex` userConfig, delivered as `CAVE_CONTEXT_BRANCH_REINDEX` via `.mcp.json` `env`; only the literal `"false"` disables (fail-open). `handlers.mjs` stays pure delegation — the side-effect lives in `server.mjs`.

## Skills
- `skills/cave-compress/SKILL.md` — **model- and user-invocable** Markdown compressor. The three fail-closed gates are unchanged (type-check → recoverability → scope), but compression is now delegated to the `compress` MCP tool (which owns the authoritative caveman ruleset and runs the rewrite in an isolated `claude` process); the skill only gates the file and applies the tool's `{ compressed, changed, valid }` result. The inline ruleset in SKILL.md is trimmed to a pointer.
