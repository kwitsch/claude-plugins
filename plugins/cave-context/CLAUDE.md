# CLAUDE.md — cave-context

One MCP server that proxies the context-mode MCP server 1-to-1 and hosts aggregated caveman+context-mode hook handlers. Replaces both plugins.

## Behavior
- **Runtime launcher** `bin/bnx.sh` (chmod +x) owns runtime selection — every `.mjs` (server + command hooks) and the upstream `context-mode` package launch through it. It prepends `${HOME}/.local/bin` + `${HOME}/.bun/bin` to PATH (use `${HOME}`, never `~`), detects bun via `command -v bun`, and dispatches on the first arg: a `*.mjs` → `bun <script>` (else `node <script>`); an npm package → `bun x <pkg>` (else `npx -y <pkg>`). No arg → stderr + exit 64. `.mcp.json` + the two command hooks in `hooks.json` (SessionStart, PreCompact) use exec form `command: bin/bnx.sh`, `args: [<.mjs or pkg>]`.
- `mcp/server.mjs`: launches `context-mode` upstream (via `bnx.sh`, default `proxy.mjs` cmd resolved with `import.meta.url`), re-exposes every `ctx_*` tool verbatim, also serves `hook_*` tools. **No in-file bun re-exec shim** — `bnx.sh` owns runtime selection; the module just calls `startServer()`.
- `mcp/subagent-watch.mjs`: zero-dep scan used by `handleStop` — `subagentsDirFor(transcript_path)` and `detectInflightSubagents(transcript_path, nowMs)`. Imported by `handlers.mjs`, not a hook entrypoint, so no executable bit required.
- `hooks/hooks.json` (handler-type rationale follows `.claude/rules/hooks-mcp-server.md` + the event matrix — each command hook is justified by a *specific* reason, not a blanket "early-lifecycle" claim): SessionStart = `command` hook (`hooks/sessionstart.mjs` via `bnx.sh`) — **pre-connect**: the MCP server is not up on first run, so `mcp_tool` would fail open; emits the always-full caveman ruleset as `additionalContext` (no state to seed). PreCompact = `command` hook (`hooks/precompact.mjs` via `bnx.sh`) — **fail-open-sensitive side-effect**: it delegates context-mode's pre-context-loss snapshot, which must fire even if the server is momentarily down (the event itself is `full`/mid-session in the matrix — connectivity is *not* the reason; an `mcp_tool` hook would fail open exactly when the snapshot matters). UserPromptSubmit + PreToolUse + PostToolUse = `mcp_tool` → `hook_*` — mid-session, non-blocking, server connected. UserPromptSubmit is `limited` in the matrix (per-prompt 30 s round-trip), so it was a deliberate choice over a command hook: drops the per-prompt `node` spawn + the extra shim file, at the cost of a per-prompt MCP round-trip and a first-prompt server-connect race (reminder/prompt-capture may be dropped on turn 1 — low impact, SessionStart already injected the fresh ruleset that turn). No ConfigChange hook — the `caveman_level` userConfig it reacted to was removed (level is fixed at full, nothing to re-seed live). Stop = `mcp_tool` → `hook_stop` — mid-session, non-blocking, server connected (per the hooks decision tree, `Stop` prefers `mcp_tool`). **Native, NOT delegated** to context-mode (which has no `stop` route): `handleStop` scans the session `subagents/` dir (derived from `transcript_path` by stripping `.jsonl`, via `mcp/subagent-watch.mjs`) for in-flight `agent-*.jsonl` transcripts (last record lacks `end_turn`, mtime < 180 s) and returns a soft `decision:"block"` with watchdog guidance in `reason` (the field Claude Code surfaces to the model on a Stop block — NOT `hookSpecificOutput.additionalContext`, which is for other hook types), guarded by `stop_hook_active` (blocks at most once per stop-sequence) and fully fail-open (any error / server-down → stop proceeds). The block steers the orchestrator to arm a bounded `Bash run_in_background` completion-watchdog rather than bare-wait on a push notification. Stop has no matcher, so the PreToolUse/PostToolUse `hook_`-self-match reentrancy concern does not apply.
- caveman reimplemented in `mcp/caveman.mjs` — **fixed at level `full`**: no level switching (lite/ultra removed), no off switch, no userConfig, no runtime state. The module is just two text builders — `rulesetText()` (SessionStart ruleset) and `reminderText()` (per-turn reminder), both hardcoded to full; `sessionprompt.mjs` builds the SessionStart prompt from `rulesetText()`. **SessionStart is the one event NOT delegated** — it is handled wholly by cave-context's own ruleset (context-mode's context-routing guidance is reimplemented inline in `sessionprompt.mjs`'s "## Context routing" section), so delegating would double-inject. The four mid-session events are delegated to context-mode via `bnx.sh context-mode hook claude-code <event>` (default `delegate.mjs` cmd resolved with `import.meta.url`). Platform token `claude-code` and the **lowercase** delegated event keys (`pretooluse`/`posttooluse`/`precompact`/`userpromptsubmit`) are verified against context-mode 1.0.162 `cli.bundle.mjs` routing map — `sessionstart` is also a valid key there but is verified-but-unused (not delegated, per above). The CLI `process.exit(1)`s silently on an unknown platform/event key, so `delegate.mjs` lowercases the event before invoking it.
- Reentrancy: PreToolUse/PostToolUse matchers must never match `hook_` tools.

## Tests
`test/cave-context/test.bats` (bats) + `test/cave-context/*.test.mjs` (node --test). Run:
```bash
BATS_LIB_PATH=/usr/lib/bats bats test/cave-context/
node --test test/cave-context/*.test.mjs
```
