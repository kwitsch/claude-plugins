# Claude Code Hooks — Mechanics Reference

> Harness-optimized knowledge file. Directives, not prose. Source: code.claude.com/docs/en/hooks + code.claude.com/docs/en/hooks-guide, verified 2026-07-25.
> Scope: event catalog, config schema, matchers, I/O, exit codes, decision control, scopes.
> For choosing a handler `type` (command/.sh/.mjs/binary vs http/mcp_tool/prompt/agent), see **hook-handler-selection.md** — not repeated here.

## Model: three nesting levels

1. **Hook event** — lifecycle point (`PreToolUse`, `Stop`, …).
2. **Matcher group** — `matcher` filter for when it fires.
3. **Hook handler** — the `command`/`http`/`mcp_tool`/`prompt`/`agent` that runs.
   "Hook" alone = the feature. Multiple matched handlers run in parallel; identical handlers are deduplicated (command by command+args, http by url).

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(rm *)",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "args": []
          }
        ]
      }
    ]
  }
}
```

## Hook locations / scope

| Location                      | Scope                  | Shareable          |
| ----------------------------- | ---------------------- | ------------------ |
| `~/.claude/settings.json`     | all your projects      | no (local machine) |
| `.claude/settings.json`       | one project            | yes (committable)  |
| `.claude/settings.local.json` | one project            | no (gitignored)    |
| managed policy settings       | org-wide               | yes (admin)        |
| plugin `hooks/hooks.json`     | when plugin enabled    | yes (bundled)      |
| skill/agent frontmatter       | while component active | yes (in component) |

- Enterprise `allowManagedHooksOnly` blocks user/project/plugin hooks; force-enabled `enabledPlugins` hooks are exempt.
- File-watcher picks up direct settings edits automatically.

## Event catalog (cadence + when)

Cadence: once/session (SessionStart, SessionEnd), once/turn (UserPromptSubmit, Stop, StopFailure), per tool call (PreToolUse, PostToolUse — both skipped for `EndConversation` calls).

| Event                               | Fires                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SessionStart`                      | session begins/resumes. command + mcp_tool only                                                                                                                 |
| `Setup`                             | `--init-only`, or `--init`/`--maintenance` in `-p`. command + mcp_tool only                                                                                     |
| `InstructionsLoaded`                | CLAUDE.md / `.claude/rules/*.md` loaded (eager + lazy). observability only                                                                                      |
| `UserPromptSubmit`                  | prompt submitted, before processing. can block                                                                                                                  |
| `UserPromptExpansion`               | user slash command expands to prompt, before Claude. can block. catches the `/skill` direct path that `PreToolUse` misses                                       |
| `PreToolUse`                        | before a tool call. can block / rewrite input. never fires for `@`-referenced file reads (inlined while building the prompt, no tool call) or `EndConversation` |
| `PermissionRequest`                 | a permission dialog appears                                                                                                                                     |
| `PermissionDenied`                  | auto-mode classifier denied; `{retry:true}` lets model retry                                                                                                    |
| `PostToolUse`                       | tool succeeded. can feed back / rewrite output                                                                                                                  |
| `PostToolUseFailure`                | tool failed                                                                                                                                                     |
| `PostToolBatch`                     | full parallel batch resolved, before next model call. can stop loop                                                                                             |
| `Notification`                      | Claude Code sends a notification                                                                                                                                |
| `MessageDisplay`                    | while assistant text streams. display-only; can rewrite on-screen text                                                                                          |
| `SubagentStart` / `SubagentStop`    | subagent spawned / finished                                                                                                                                     |

| `Stop`                              | Claude finishes responding. can prevent stop                                                                                                                    |
| `StopFailure`                       | turn ends on API error. output + exit ignored                                                                                                                   |
| `TeammateIdle`                      | agent-team teammate about to idle. can keep working                                                                                                             |
| `ConfigChange`                      | config file changed mid-session. can block (except policy)                                                                                                      |
| `CwdChanged`                        | working dir changed (e.g. `cd`). no matcher                                                                                                                     |
| `FileChanged`                       | watched file changed; `matcher` = filenames to watch                                                                                                            |
| `WorktreeCreate` / `WorktreeRemove` | worktree created/removed. Create: any non-zero aborts                                                                                                           |
| `PreCompact` / `PostCompact`        | before/after compaction. Pre can block                                                                                                                          |
| `Elicitation` / `ElicitationResult` | MCP requests user input / after response                                                                                                                        |
| `SessionEnd`                        | session terminates                                                                                                                                              |

## Matcher semantics

`matcher` evaluation by content:

| Value                                       | Treated as                                                                                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `*`, `""`, omitted                          | match all                                                                                                                                                    |
| only letters/digits/`_`/`-`/spaces/`,`/`\|` | exact string, or list of exacts separated by `\|` or `,` with optional surrounding whitespace (`Edit\|Write`, `Edit, Write`)                                 |
| any other char                              | JavaScript regex, unanchored (`^Notebook`, `mcp__memory__.*`; unanchored means `Edit.*` also matches `NotebookEdit` — use `^Edit$` for a whole-string match) |

- `FileChanged`/`StopFailure` use a narrower exact-match set: letters/digits/`_`/`|` only (no hyphen/space/comma) — a hyphen, space, or comma there keeps the matcher on the regex path, and only `|` separates alternatives for those two events.
- MCP tools appear as `mcp__<server>__<tool>`. To match a whole server you MUST append `.*` (`mcp__memory__.*`) — `mcp__memory` is exact-string and matches nothing.
- What the matcher filters per event: tool events → `tool_name`; `SessionStart` → `startup|resume|clear|compact|fork` (version >= 2.1.214: `fork`; earlier versions report a forked session as `resume`); `Setup` → `init|maintenance` (which CLI flag fired it); `SubagentStart/Stop` → agent type (`general-purpose`, `Explore`, `Plan`, or custom/plugin-scoped names); `PreCompact/PostCompact` → `manual|auto`; `SessionEnd` → `clear|resume|logout|prompt_input_exit|bypass_permissions_disabled|other`; `Notification` → type (`permission_prompt`, `idle_prompt`, `auth_success`, `elicitation_dialog`, `elicitation_complete`, `elicitation_response`, `agent_needs_input`, `agent_completed` — last two require agent-view + version >= 2.1.198); `StopFailure` → error type (`rate_limit`, `overloaded`, `authentication_failed`, `oauth_org_not_allowed`, `billing_error`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, `unknown`); `InstructionsLoaded` → load reason; `ConfigChange` → `user_settings|project_settings|local_settings|policy_settings|skills`; `UserPromptExpansion` → command name; `Elicitation*` → MCP server.
- A plugin-scoped agent type (`my-plugin:reviewer`) contains `:` → regex path, not exact-match → anchor it (`^my-plugin:reviewer$`) or it also matches longer names.
- No matcher (silently ignored if set): `UserPromptSubmit`, `PostToolBatch`, `Stop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`, `WorktreeCreate`, `WorktreeRemove`, `CwdChanged`, `MessageDisplay`.
- `FileChanged` input also carries `event`: `"change"` (modified), `"add"` (created), or `"unlink"` (deleted).

### `if` field (per-handler, tool events only)

- version >= 2.1.85: required (earlier versions ignore `if` and run on every matched call).
- Permission-rule syntax against tool name + args: `Bash(git *)`, `Edit(*.ts)`. Exactly one rule; no `&&`/`||`/list — use separate handlers.
- Directory patterns are single-segment: `Edit(src/**)` matches only `src` in the working directory; use `Edit(**/src/**)` for a `src` at any depth. version >= 2.1.214; earlier versions matched any depth for the single-segment form.
- Only evaluated on `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `PermissionDenied`; on other events a handler with `if` never runs.
- Bash matching: leading `VAR=val` stripped; each subcommand and `$()`/backtick content checked; patterns more specific than the command name run anyway on `$()`/backtick/`$VAR`. **Fails OPEN on unparseable Bash** → never gate security with `if`; use permission rules.

## Handler types (field tables)

Five `type` values: `command` | `http` | `mcp_tool` | `prompt` | `agent`. **Choice criteria → hook-handler-selection.md.**

Common fields (all types): `type` (req), `if`, `timeout` (defaults: 600s command/http/mcp_tool, 30s prompt, 60s agent; UserPromptSubmit lowers to 30, MessageDisplay to 10), `statusMessage`, `once` (skill-frontmatter only; ignored in settings/agent).

- `command`: `command` (req), `args` (→ exec form), `async`, `asyncRewake` (bg + wake Claude on exit 2), `shell` (`bash`|`powershell`).
- `http`: `url` (req), `headers` (`$VAR` interp), `allowedEnvVars` (required for any interp; unlisted → empty).
- `mcp_tool`: `server` (req, must be connected), `tool` (req), `input` (`${path}` substitution from hook JSON).
- `prompt`/`agent`: `prompt` (req; `$ARGUMENTS` = hook input JSON — omit it and the input JSON is appended to the prompt instead; `\$` escapes a literal `$`), `model` (default fast model, Haiku), `continueOnBlock` (default false; implemented as `continue:true` on the resulting `decision:"block"` — see per-event list below). Output contract = JSON `{"ok":true|false,"reason":...}` (NOT exit codes / `decision`). `ok:false` per event: Stop/SubagentStop → `reason` fed back, keeps working; PreToolUse → tool denied, and by default the turn ends with `reason` shown as a chat warning, `continueOnBlock:true` returns `reason` to Claude as the tool error so it can adjust and continue (equivalent to a command hook's `permissionDecision:"deny"`) — version >= 2.1.210; earlier versions used the tool-error-and-continue path as the default; PostToolUse → turn ends + `reason` shown as warning by default, `continueOnBlock:true` feeds `reason` back and continues instead; PostToolBatch/UserPromptSubmit/UserPromptExpansion → turn ends, warning, **regardless of** `continueOnBlock`; PostToolUseFailure/TaskCreated → `reason` returned as tool error + turn continues, regardless of `continueOnBlock`; TaskCompleted → same tool-error-and-continue when a task is marked complete mid-turn, but when it fires because a teammate stops it behaves like TeammateIdle (halts by default); TeammateIdle → stops by default + warning, `continueOnBlock:true` keeps it working instead; PermissionRequest/PermissionDenied → `ok:false` has **no effect** (PermissionDenied's only readable output, `retry`, isn't settable by prompt/agent) — use a `command` hook for these two. `agent` is EXPERIMENTAL (may change; prefer `command` for production); 60s default timeout, up to 50 tool-use turns.

### Which events support which handler types

- All 5 types (`command`/`http`/`mcp_tool`/`prompt`/`agent`): `PermissionDenied`, `PermissionRequest`, `PostToolBatch`, `PostToolUse`, `PostToolUseFailure`, `PreToolUse`, `Stop`, `SubagentStop`, `TaskCompleted`, `TaskCreated`, `TeammateIdle`, `UserPromptExpansion`, `UserPromptSubmit`.
- `command`/`http`/`mcp_tool` only (no `prompt`/`agent`): `ConfigChange`, `CwdChanged`, `Elicitation`, `ElicitationResult`, `FileChanged`, `InstructionsLoaded`, `Notification`, `PostCompact`, `PreCompact`, `SessionEnd`, `StopFailure`, `SubagentStart`, `WorktreeCreate`, `WorktreeRemove`.
- `command`/`mcp_tool` only: `SessionStart`, `Setup`.

### Exec vs shell form (command)

- `args` present → **exec form**: `command` resolved on PATH, spawned directly; each `args` element = one arg, no shell, no quoting; placeholders substituted as plain strings. Use whenever referencing a path placeholder.
- `args` absent → **shell form**: `sh -c` (macOS/Linux), Git Bash/PowerShell (Windows); enables pipes, `&&`, globs, var expansion. Quote placeholders.
- Windows: `.cmd`/`.bat` shims aren't executables → use shell form, OR exec via `node` + script path (`node` + path works everywhere).
- Path placeholders (also exported as env vars): `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}` (changes per update), `${CLAUDE_PLUGIN_DATA}` (survives updates). Both forms substitute them.
- Plugin hooks also substitute `${user_config.*}`, **exec form only**. A shell-form plugin hook whose `command` references `${user_config.*}` FAILS with an error instead of running → either set `args` (switch to exec form) or read the exported `$CLAUDE_PLUGIN_OPTION_<KEY>` env var (`$CLAUDE_PLUGIN_OPTION_WEBHOOK_URL` for a `webhook_url` option). version >= 2.1.207; earlier versions also substituted it in shell form.

## Input (stdin for command; POST body for http)

Common fields: `session_id`, `prompt_id` (UUID of the current user prompt, matches OpenTelemetry `prompt.id`; absent until first user input; version >= 2.1.196), `transcript_path` (written asynchronously → may lag the in-memory conversation and omit the current turn; for the just-finished turn's text read `last_assistant_message` on Stop/SubagentStop instead), `cwd`, `permission_mode` (not all events; values `default`/`plan`/`acceptEdits`/`auto`/`dontAsk`/`bypassPermissions` — the UI's **Manual** mode arrives as `"default"`, never `"manual"`), `effort.level` (`low`/`medium`/`high`/`xhigh`/`max`; tool-context events; also `$CLAUDE_EFFORT`), `hook_event_name`. In subagent/`--agent`: `agent_id`, `agent_type`. Only `SessionStart` may receive `model` (not guaranteed; no `$CLAUDE_MODEL`); it also gets `source` plus optional `agent_type` (from `--agent`) and `session_title` (already-set title — check it before overwriting via `sessionTitle`).
Other env vars to hooks: `$CLAUDE_CODE_REMOTE` = `"true"` in remote web environments (unset in local CLI); `$CLAUDE_CODE_BRIDGE_SESSION_ID` = active Remote Control session ID while an RC connection is live, unset otherwise (version >= 2.1.199).
Tool events add `tool_name`, `tool_input` (`tool_use_id` on PreToolUse, PostToolUse, PostToolUseFailure, PermissionDenied). `tool_input` shape per tool — Bash `command`+`description`+`timeout`+`run_in_background`; Write `file_path`+`content`; Edit `file_path`+`old_string`+`new_string`+`replace_all`; Read `file_path`+`offset`+`limit`; Glob `pattern`+`path`; Grep `pattern`+`path`+`glob`+`output_mode`+`-i`+`multiline`; WebFetch `url`+`prompt`; WebSearch `query`+`allowed_domains`+`blocked_domains`; Agent `prompt`+`description`+`subagent_type`+`model`; AskUserQuestion `questions`+`answers` (answers maps question text → chosen label, multi-select joins with commas — Claude never sets it, supply via `updatedInput` to answer programmatically); ExitPlanMode `plan`+`planFilePath` (both injected by Claude Code from the on-disk plan file, not the literal model tool call) +`allowedPrompts` (deprecated, ignored, version >= 2.1.205). PostToolUse Agent `tool_response` carries the subagent's final `content` text blocks plus usage telemetry (`status`, `agentId`, `totalTokens`, `totalDurationMs`, `totalToolUseCount`, `usage`, `resolvedModel` [≥v2.1.174], `modelsUsed` [≥v2.1.212; models in order with consecutive repeats collapsed, set only when the model was swapped mid-run]) for per-subagent cost logging; ≥v2.1.198 subagents run in the background by default, so an omitted `run_in_background` now also yields `status:"async_launched"` (background responses carry only `status`/`agentId`/`description`/`prompt`/`outputFile`/`resolvedModel` — no usage fields). PostToolUse ExitPlanMode `tool_response` = `{plan, filePath, …}` — read `tool_response.plan` rather than re-reading the file. PostToolUse/PostToolUseFailure also add `duration_ms` (tool exec time; excludes permission-prompt/PreToolUse time); PostToolUseFailure adds `error`+`is_interrupt` and fires only for a tool that actually started executing — a validation rejection (unknown tool name, schema/tool-specific validation failure) fires neither `PreToolUse` nor this event, and a permission denial fires `PreToolUse` but not this event; PermissionDenied adds `reason` (the fixed text `Blocked by classifier` in most sessions, or the classifier's written explanation when the session's classifier model provides one); PermissionRequest adds optional `permission_suggestions` (array of "always allow" entries the dialog would show — same shape as `updatedPermissions` entries, see below).
`PostToolBatch` adds `tool_calls`: array of `{tool_name, tool_input, tool_use_id, tool_response}` — `tool_response` here is the serialized `tool_result` content the model sees (e.g. line-numbered text for Read), which differs from `PostToolUse`'s structured `tool_response` object (e.g. `{filePath, success}` for Write).
`TaskCreated`/`TaskCompleted` add `task_id`, `task_subject`, optional `task_description`, `teammate_name`, `team_name` (deprecated, session-derived, to be removed). `TeammateIdle` adds `teammate_name`, `team_name` (same deprecation).
`SubagentStart` adds `agent_id`, `agent_type`. `WorktreeCreate` adds `name` (slug id for the new worktree, e.g. `bold-oak-a3f2`); `WorktreeRemove` adds `worktree_path` (the path `WorktreeCreate` returned).
`UserPromptSubmit` adds `prompt` (the submitted text). `Setup` adds `trigger` (`init`/`maintenance`). `SessionEnd` adds `reason` (same values as its matcher). `ConfigChange` adds `source` + optional `file_path`. `CwdChanged` adds `old_cwd`, `new_cwd`. `Notification` adds `message`, `notification_type`, optional `title`.
`PreCompact` adds `trigger`+`custom_instructions` (manual `/compact` args; empty on auto). `PostCompact` adds `trigger`+`compact_summary` (the generated conversation summary).
`Elicitation` adds `mcp_server_name`, `message`, optional `mode` (`form`/`url`), `url`, `elicitation_id`, `requested_schema`. `ElicitationResult` adds `mcp_server_name`, `action`, optional `mode`, `elicitation_id`, `content`.
`InstructionsLoaded` adds `file_path`, `memory_type` (`User`/`Project`/`Local`/`Managed`), `load_reason` (`session_start`/`nested_traversal`/`path_glob_match`/`include`/`compact`), `globs` (path_glob_match only), `trigger_file_path` (lazy loads), `parent_file_path` (include loads).
`UserPromptExpansion` adds `expansion_type` (`slash_command` for skills/commands, `mcp_prompt` for MCP server prompts), `command_name`, `command_args`, `command_source`, `prompt`.
`MessageDisplay` adds `turn_id`, `message_id`, `index` (0-based batch #), `final` (true on the message's last batch), `delta` (new text since prior batch). Fires once per rendered batch of completed lines in interactive mode; in non-interactive (`-p`, Agent SDK) fires once per message with `index:0`, `final:true`, `delta` = full message text. Assistant text only — a tool-call-only message with no text never fires it.
`StopFailure` adds `error`, optional `error_details`, `last_assistant_message` — here the rendered API error string (e.g. `"API Error: Rate limit reached"`), unlike `Stop`/`SubagentStop` where the same field holds Claude's conversational output.
`Stop` input adds `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons` (latter two ≥v2.1.145 — distinguish "session done" from "session paused waiting on background work"). `SubagentStop` receives the same `background_tasks`/`session_crons` (scoped to the parent session, not the subagent), plus `agent_id`, `agent_type`, `agent_transcript_path` (subagent's own transcript, nested under the parent's `subagents/` folder — distinct from `transcript_path`, the main session's).

## Exit codes (command)

- **0** = success; stdout parsed for JSON (JSON only processed on exit 0). stdout reaches Claude only on `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`; elsewhere debug log only.
- **2** = blocking error; stdout/JSON ignored, stderr fed to Claude. Effect per event below.
- **other** = non-blocking error for most events; transcript shows error notice + first stderr line; action proceeds.
- Pick ONE: exit-code signaling OR exit 0 + JSON. Not both.
- **exit 1 does NOT block** (Unix convention trap). Only exit 2 blocks. Exception: `WorktreeCreate` aborts on any non-zero.
- exit 2 while also printing JSON that fails output-schema validation still blocks (stderr becomes the reason; the validation failure only lands in the debug log). version >= 2.1.214; earlier versions treated that combination as a non-blocking error and let the action proceed.

### exit 2 effect per event

Blocks: `PreToolUse` (blocks call), `PermissionRequest` (deny), `UserPromptSubmit` (reject+erase), `UserPromptExpansion` (block expansion), `Stop`/`SubagentStop` (prevent stop), `TeammateIdle` (keep working), `TaskCreated` (rollback), `TaskCompleted` (prevent complete), `ConfigChange` (block, except policy), `PostToolBatch` (stop loop), `PreCompact` (block), `Elicitation` (deny), `ElicitationResult` (decline), `WorktreeCreate` (any non-zero fails).
No-block (stderr shown to Claude/user, or ignored): `PostToolUse`, `PostToolUseFailure`, `PermissionDenied` (use `retry:true`), `StopFailure`, `Notification`, `SubagentStart`, `SessionStart`, `Setup`, `SessionEnd`, `CwdChanged`, `FileChanged`, `PostCompact`, `WorktreeRemove`, `InstructionsLoaded`, `MessageDisplay`.

## HTTP response handling

- 2xx empty = success (≈exit 0 no output); 2xx text = context; 2xx JSON = parsed as JSON output.
- Non-2xx / connection failure / timeout = non-blocking error → proceeds. **Cannot hard-block via status alone** → return 2xx + JSON `decision:"block"` or `permissionDecision:"deny"`.

## JSON output (exit 0)

stdout must be ONLY the JSON object (shell-profile noise breaks parsing). All output strings (incl. `additionalContext`, `systemMessage`) capped at **10,000 chars** → overflow saved to file + preview.

Universal fields: `continue` (false → Claude stops entirely; precedence over decision fields), `stopReason` (shown to user, not Claude), `suppressOutput`, `systemMessage` (user warning), `terminalSequence` (emit notification on your behalf; ≥v2.1.141).

- `terminalSequence` allowlist: OSC `0`/`1`/`2` (titles), `9` (incl `9;4` progress), `99` (Kitty), `777`, bare BEL; ST/BEL terminators. Anything else (CSI, OSC 8/52/1337, colors) → field ignored. Use instead of `/dev/tty` (unavailable to hooks).
- `additionalContext` (inside `hookSpecificOutput` + `hookEventName`): injected as a system reminder at the hook's fire point; Claude reads on next request. Write as factual statements ("This repo uses `bun test`"), not imperative system commands (triggers prompt-injection defenses). Static rules → CLAUDE.md instead. Saved to transcript → stale values (timestamps/SHAs) replay on `--resume` for mid-session events; SessionStart re-runs on resume.

No decision control — can't block the `cd` or the file change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| WorktreeRemove, Notification, SessionEnd, PostCompact, InstructionsLoaded, StopFailure                                              | none                       | side effects only                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

Content rewriting: PreToolUse `updatedInput` (before run), PostToolUse `updatedToolOutput` (after; `updatedMCPToolOutput` is an MCP-only alias, prefer `updatedToolOutput`), PermissionRequest `decision.updatedInput`, UserPromptSubmit injects `additionalContext` only (can't replace prompt). Redact outbound at PreToolUse, inbound at PostToolUse.

- `updatedToolOutput` must match the tool's output shape — built-in tools return structured objects (Bash → `{stdout, stderr, interrupted, isImage}`), and a value that doesn't match the schema is silently IGNORED (original output used); MCP tool output passes through unvalidated. Model-visible only: the tool already ran, and telemetry captured the original.
- PostToolUse `decision:"block"` puts `reason` next to the tool result; Claude still sees the original output → use `updatedToolOutput` to replace it.
- **PreToolUse: top-level `decision`/`reason` are DEPRECATED** for this event → use `hookSpecificOutput.permissionDecision`/`permissionDecisionReason`. (Deprecated `approve`/`block` → `allow`/`deny`.) PostToolUse/Stop still use top-level `decision`.
- **PreToolUse `permissionDecision:"allow"` alone is insufficient** for `AskUserQuestion`/`ExitPlanMode` (both require user interaction and normally block in `-p`) — pair it with `updatedInput` carrying the answer (an `answers` object for `AskUserQuestion`). ≥v2.1.199: an MCP tool whose server marks it `_meta["anthropic/requiresUserInteraction"]` is stricter still — no hook can skip its approval prompt via `"allow"`, with or without `updatedInput`. Connector tools an org set to `ask` also prompt regardless of `"allow"`.
- **`"ask"` in auto mode** forces the prompt: the classifier may still deny the call but can no longer approve it silently. version >= 2.1.211; earlier versions let the classifier approve a Bash command running outside the sandbox without showing the requested prompt (its own safety rules still applied, and a hook `"deny"` was always honored).
- **`defer`** (≥v2.1.89, `-p` only): pauses Claude with the pending tool call preserved (`stop_reason:"tool_deferred"`, `deferred_tool_use.{id,name,input}` in the SDK result); the calling process resumes via `claude -p --resume <session-id>`, re-triggering the same `PreToolUse` call, then returns `"allow"` + `updatedInput` with the answer. Only works when the turn makes a single tool call — a batch of calls ignores `"defer"` with a warning. Session persists until resumed, subject to `cleanupPeriodDays` (default 30). If the deferred tool is unavailable on resume (e.g. its MCP server disconnected), the process exits `stop_reason:"tool_deferred_unavailable"`, `is_error:true`. `--resume` restores the permission mode active when deferred, except `plan`/`bypassPermissions` (never restored) and `auto` (restored only if the account still meets the auto-mode requirements); passing `--permission-mode` explicitly on resume overrides the restored value.
- **Stop**: fires whenever Claude finishes responding (not only at task completion); does NOT fire on user interrupts (API errors fire `StopFailure` instead). Block cap: Claude Code overrides a Stop hook after it blocks 8 consecutive times without progress. Read input field `stop_hook_active` (true once a continuation already triggered) → exit 0 early. Raise cap via env `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`. On `SubagentStop`, `decision:"block"` + `reason` keeps the subagent running with `reason` as its next instruction — to inject context into the PARENT session after a subagent returns, use `PostToolUse` on the `Agent` tool instead.
- **Multi-hook merge**: every matched hook runs to completion before merge — a `deny` does NOT stop sibling hooks (don't rely on it to suppress another hook's side effects). Multiple PreToolUse `updatedInput`: last-to-finish wins, order non-deterministic → avoid >1 hook rewriting the same tool input.

## SessionStart specifics

- `CLAUDE_ENV_FILE` (also Setup/CwdChanged/FileChanged): append `export` lines → persist env into later Bash. Use `>>`.
- `reloadSkills:true` re-scans skill/command dirs after SessionStart hooks (skills the hook installed become available same session). Re-runs on resume with `source:"resume"`, or `"fork"` under `--fork-session`.
- Plain stdout already reaches Claude here → context-only hooks can skip JSON.

## Setup specifics

- Fires ONLY on `claude --init-only`, or `--init`/`--maintenance` combined with `-p`; never on normal interactive startup. `--init-only` also runs `SessionStart` (`startup` matcher), then exits without starting a conversation.
- Can't block: any non-zero exit (incl. 2) shows stderr as a `<hook name> hook error` notice; execution continues. In `-p`, hook output shows only with `--verbose`.
- Unlike SessionStart, plain stdout does NOT reach Claude here → return `additionalContext` JSON (multiple hooks' values concatenate). Setup input carries `trigger` (`init`/`maintenance`).
- Setup does not fire on every launch → a plugin needing a dependency must check-and-install on first use (e.g. test for `${CLAUDE_PLUGIN_DATA}/node_modules`), not rely on Setup.

## Async hooks (`async`/`asyncRewake`, `command` only)

- Response fields that control behavior (`decision`, `permissionDecision`, `continue`, …) have no effect — the triggering action has already proceeded by the time the hook completes.
- Output delivered on the next conversation turn; if idle, waits for the next user interaction. Exception: `asyncRewake` + exit 2 wakes Claude immediately even while idle.
- Malformed JSON output: fields with the wrong type are dropped (warning under `--debug`); version >= 2.1.202 fixes a prior crash-on-malformed-JSON that recurred on every resume of the session.
- Completion notifications suppressed by default; show them via `Ctrl+O` (verbose) or `--verbose`.

## SessionEnd specifics

- Default timeout **1.5s** (not the general 600s) — applies to session exit, `/clear`, and switching sessions via interactive `/resume`. Budget auto-raises to the highest per-hook `timeout` configured in settings files, up to 60s; timeouts on plugin-provided hooks don't raise it. Override explicitly via env `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` (milliseconds).

## Hooks in skills/agents (frontmatter)

- Same config format; scoped to component lifetime; cleaned up on finish. All events supported.
- Subagent `Stop` auto-converts to `SubagentStop`. `once:true` honored ONLY in skill frontmatter.
- Frontmatter hooks in a PROJECT subagent run only after the workspace-trust dialog is accepted for the folder the agent file came from. version >= 2.1.218; earlier versions ran them from untrusted folders.

## /hooks menu & disabling

- `/hooks` = read-only browser; per type `[command|http|mcp_tool|prompt|agent]` + source (`User`/`Project`/`Local`/`Plugin`/`Session`/`Built-in`). Edit JSON to change.
- `disableAllHooks:true` disables all (no per-hook disable). Respects managed hierarchy — only managed-level can disable managed hooks.

## Hard constraints / security

- PreToolUse fires BEFORE any permission-mode check (every mode, incl. `dontAsk`) → `permissionDecision:"deny"` blocks even in `bypassPermissions` / `--dangerously-skip-permissions`. Reverse fails: `"allow"` never overrides settings deny rules, ask rules, org-set-to-`ask` connector tools, or `requiresUserInteraction` MCP tools (hooks tighten, never loosen). Deny rules from any scope (incl. managed) outrank hook approvals.
- No controlling terminal (macOS/Linux ≥v2.1.139): no `/dev/tty`. Surface via `systemMessage`; notify via `terminalSequence`.
- Security/irreversible gates → permission system, NOT hooks. `if` and http/mcp_tool fail OPEN (see hook-handler-selection.md).
- `command` holds no state between fires; stateful/expensive init → persistent server via `mcp_tool`/`http`.
- Hook-only `mcp_tool` triggers are config-driven; keep them off the model tool surface to avoid context/token cost.
