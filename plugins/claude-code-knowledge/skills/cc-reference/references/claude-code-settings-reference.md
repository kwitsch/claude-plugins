## settings.json: locations & scope precedence

Scopes from highest to lowest priority (higher overrides lower for scalar keys; arrays merge):

| Scope              | File path                           | Shareable              |
| ------------------ | ----------------------------------- | ---------------------- |
| Enterprise managed | platform/MDM/plist/HKLM/HKCU/remote | Yes (admin-controlled) |
| Command-line args  | `--allowedTools`, `--model`, etc.   | No (session only)      |
| Project local      | `.claude/settings.local.json`       | No (gitignored)        |
| Project            | `.claude/settings.json`             | Yes (commit to repo)   |
| User               | `~/.claude/settings.json`           | No (machine-local)     |

- Array settings (`permissions.allow`, `sandbox.filesystem.allowWrite`, etc.) **concatenate and deduplicate** across scopes rather than override.
- Exception: `fallbackModel` — the highest-precedence scope that defines it supplies the entire chain.
- `version >= 2.1.175:` `availableModels` — a managed/policy value replaces lower-precedence entries entirely.
- Within the managed tier only ONE source applies; the others are ignored, not merged. Highest first: a configured `policyHelper` script's output (which then becomes the ONLY managed source, and parent settings are never merged) → remote/server-managed → MDM/OS policy → file-based (`managed-settings.json` + `managed-settings.d/*.json` merged) → HKCU registry.
- `version >= 2.1.211:` `.claude/settings.local.json` is read/written at the git repository root (resolved through worktrees to the main checkout), so one file covers every subdirectory. Earlier versions used the launch directory; a file left there is still read, and the repo-root value wins on a key collision.
- `Read`/`Edit` `/path` rules in local settings still anchor at the ORIGINAL cwd, not the repo root.
- The repo-root local-settings file applies only when the repo root is owned by your user and isn't your home directory, and not on Windows; otherwise (and outside a git repo) the file stays at the starting directory instead.
- `/cd <path>` moves the primary working directory. `version >= 2.1.246:` the new directory's project settings, hooks, MCP servers, and skills apply immediately; earlier versions waited until the session was resumed.
- `--settings <file-or-json>` merges per-key like any other layer; omitted keys leave lower layers intact.
- Windows: `~/.claude` resolves to `%USERPROFILE%\.claude`.
- Run `/status` → **Status** tab → `Setting sources` line to see which files are loaded.

| `useAutoModeDuringPlan`                         | Boolean (default `true`); let `plan` mode use auto-mode semantics when auto mode is available. | `effortLevel`                                   | Persist effort: `"low"`/`"medium"`/`"high"`/`"xhigh"`. `max`/`ultracode` are session-only, not accepted here                                                                                                                                                                                                                                                                                                                                                                                              |
| `switchModelsOnFlag`                            | Boolean, default `true`; auto-switch to the fallback model when a safety classifier flags a request (Fable 5/Opus 5) and continue. `false` pauses instead, offering a choice between switching and editing the prompt. | `companyAnnouncements`                          | Array of announcement strings cycled at random and shown to users at session start; project and managed scope                                                                                                                                                                                                                                                                                                                                                                                             |
| `spinnerTipsEnabled`                            | Boolean; show spinner tips                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `showThinkingSummaries`                         | Boolean, default `false`; show extended-thinking summaries. When unset/`false` the API redacts thinking blocks to a collapsed stub. | `skillOverrides`                                | `version >= 2.1.129:` per-skill visibility map keyed by skill name — `"on"`/`"name-only"`/`"user-invocable-only"`/`"off"`; hides or collapses a skill without editing its SKILL.md. | `outputStyle`                                   | Output-style name; see Output styles section                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `statusLine`                                    | Status line config object; see Statusline section                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `subagentStatusLine`                            | Per-subagent row body config object; see Statusline section                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `sandbox`                                       | Sandbox config object; see Sandboxed Bash tool section                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `enabledPlugins`                                | Map `"plugin-name@marketplace-name": true/false` (NOT an array); a plugin with no entry at any scope falls back to its `defaultEnabled` value                                                                                                                                                                                                                                                                                                                                                             |

| `hooks`                                         | Lifecycle event hook config; see hooks reference                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `env`                                           | Map of env vars applied to every session and to subprocesses Claude Code spawns. `""` overrides a shell export with an empty string, which counts as unset for provider selection (subprocesses still inherit the empty value). `NO_COLOR`/`FORCE_COLOR` set here reach only subprocesses — set them in your shell to change Claude Code's own colors. `version >= 2.1.195:` identity vars the hosting environment sets (e.g. `CLAUDE_CODE_REMOTE`, `CLAUDE_CODE_ACCOUNT_UUID`) are ignored when set here |
| `allowedHttpHookUrls`                           | Allowlist of URL patterns HTTP hooks may target (`*` wildcard); undefined = no restriction, `[]` = block all. | `httpHookAllowedEnvVars`                        | Allowlist of env var names HTTP hooks may interpolate into headers; effective set is intersection per hook. Arrays merge across sources                                                                                                                                                                                                                                                                                                                                                                   |
| `allowManagedHooksOnly`                         | Boolean (managed only); only managed/SDK hooks + hooks from managed-`enabledPlugins` plugins load                                                                                                                                                                                                                                                                                                                                                                                                         |
| `disableAllHooks`                               | Boolean; disable all hooks AND any custom status line                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `disableAgentView`                              | Boolean; disable background agents and the agent panel (`claude agents`, `--bg`, `/background`, supervisor); equivalent to `CLAUDE_CODE_DISABLE_AGENT_VIEW`                                                                                                                                                                                                                                                                                                                                               |
| `disableSkillShellExecution`                    | Boolean; replace `!` blocks with `[shell command execution disabled by policy]` (user/project/plugin/add-dir sources; bundled/managed exempt)                                                                                                                                                                                                                                                                                                                                                             |
| `includeGitInstructions`                        | Boolean, default `true`; include built-in commit/PR instructions + git-status snapshot in system prompt; `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` env takes precedence                                                                                                                                                                                                                                                                                                                                      |

| `parentSettingsBehavior`                        | `version >= 2.1.133:` (managed only) `"merge"` lets embedder-supplied policy tighten (not loosen) under the admin tier; default `"first-wins"`                                                                                                                                                                                                                                                                                                                                                            |
| `apiKeyHelper`                                  | Custom command (run via system shell: `/bin/sh` on macOS/Linux, `cmd` on Windows) that emits an auth value sent as `X-Api-Key` and `Authorization: Bearer`; reloaded on settings file change. | `askUserQuestionTimeout`                        | `version >= 2.1.198:` opt-in AFK auto-continue for `AskUserQuestion`; `"never"` disables, an interval string (e.g. `"5m"`) enables; `CLAUDE_AFK_TIMEOUT_MS` overrides per session and turns it on even when unset                                                                                                                                                                                                                                                                                         |
| `allowManagedMcpServersOnly`                    | Boolean (managed only); only `allowedMcpServers` from managed settings are admitted; `deniedMcpServers` still merges from all sources                                                                                                                                                                                                                                                                                                                                                                     |
| `forceLoginOrgUUID`                             | (Managed only) UUID string or array; requires claude.ai account logins to belong to a listed org; empty array fails closed; single UUID pre-selects that org during login                                                                                                                                                                                                                                                                                                                                 |
| `policyHelper`                                  | (Managed only — MDM or system `managed-settings.json`) path to an admin executable that computes managed settings at startup; its output replaces ALL other managed sources when it runs; ignored from user/project/HKCU/server-managed scopes                                                                                                                                                                                                                                                            |
| `strictKnownMarketplaces`                       | (Managed only) allowlist of plugin marketplace source objects; undefined = no restrictions, `[]` = lockdown; alias `allowedMarketplaces` `version >= 2.1.232:`; owner wildcard `"acme-corp/*"` accepted `version >= 2.1.223:` in this key only                                                                                                                                                                                                                                                            |
| `disableSideloadFlags`                          | (Managed only) `true` rejects `--plugin-dir`, `--plugin-url`, `--agents`, `--mcp-config` CLI flags at startup; a `--mcp-config` with only in-process `type:"sdk"` entries is still accepted; pair with `allowedMcpServers` for per-server MCP control. `version >= 2.1.193:`                                                                                                                                                                                                                              |

## Permissions

### Rule syntax

```
ToolName                      # bare name: matches any call to ToolName
ToolName(*)                   # equivalent to the bare name
ToolName(glob)                # positional-arg match: glob against first argument
ToolName(prefix *)            # prefix glob (trailing space + * is prefix match)
mcp__server                   # all tools from a specific MCP server
mcp__server__toolname         # specific MCP tool
mcp__server__*                # all tools from a specific MCP server (allow only)
*                             # deny/ask: every tool; NOT valid in allow rules
mcp__*                        # deny/ask: every MCP tool; NOT valid in allow rules
```

- Evaluation order: `deny` → `ask` → `allow`; first match wins, specificity does NOT reorder. A broad deny blocks even a narrower allow; a matching ask prompts even with a narrower allow.
- Allow rules: tool-name globs accepted **only** after a literal `mcp__<server>__` prefix (server segment must be glob-free); bare globs like `"*"` or `"B*"` in allow are skipped with a warning.
- Deny/ask rules: accept glob patterns in the tool-name position; pattern must match the full name (`"*"` = every tool, `"mcp__*"` = every MCP tool).
- A deny rule matching a bare tool name (or a bare-name glob) removes that tool from Claude's context; a scoped rule like `Bash(rm *)` leaves the tool present and blocks matching calls.
- `EndConversation` is the exception to bare-name removal: no deny rule can remove it while any other tool remains, and an ask rule never prompts for it.
- A deny/ask rule whose tool name matches no known tool produces a startup warning (tool names with `_` or `*` are exempt).
- Use canonical tool names: the transcript label can differ (e.g. `Stop Task` → canonical `TaskStop`); rules/hook matchers match the canonical name only.
- Project `.claude/settings.json` `permissions.allow` + `additionalDirectories` are read but NOT applied until the workspace trust dialog is accepted (trust is keyed on the git repo root); `deny`/`ask` are unaffected since they only restrict. `.claude/settings.local.json` goes through the same check whenever the repo could have supplied it (committed, or `.claude` is a symlink); it is exempt outside a git repo or inside your own config home (`CLAUDE_CONFIG_DIR`).
- A `PreToolUse` hook cannot override rules: deny/ask are evaluated regardless of an `"allow"` decision. A hook exiting 2 blocks BEFORE rules are evaluated, so it also beats allow rules. Hooks run for every tool except `EndConversation`.

### Input-parameter matching (deny/ask only)

`Tool(param:value)` matches a top-level scalar input field set to that exact value (allow rules keep each tool's own specifier syntax):

| Rule                           | Matches                                                                             |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| `Agent(model:opus)`            | Agent calls requesting the `opus` alias (literal, pre-normalization; not a full ID) |
| `Agent(isolation:worktree)`    | Agent calls requesting a git worktree                                               |
| `Bash(run_in_background:true)` | Bash calls running in background                                                    |

- One parameter per rule; `*` is a wildcard; an omitted param is never matched (`Agent(model:*)` skips a call with no `model`).
- Canonicalized fields are NOT matchable this way: `command` (Bash/PowerShell), `file_path` (Read/Edit/Write), `path` (Grep/Glob), `notebook_path` (NotebookEdit), `url` (WebFetch) — such rules are ignored with a startup warning. Use `Bash(rm *)`, `Read(./path)`, `WebFetch(domain:host)` instead.

### Per-tool specifiers

- `Bash(cmd arg)` / `PowerShell(...)`: command string as a glob, wildcard at any position; recognizes separators (`&&`, `||`, `;`, `|`, `|&`, `&`, newlines) and matches each subcommand independently.
  <!-- markdownlint-disable-next-line MD038 -- the code span deliberately shows a leading space before the asterisk: `:*` is equivalent to a trailing SPACE + `*`, not a bare `*` -->
  `:*` suffix == trailing ` *`, recognized ONLY at the end of a pattern (in `Bash(git:* push)` the colon is literal).
  - Stripped wrappers: `timeout`, `time`, `nice`, `nohup`, `stdbuf`, the builtins `command`/`builtin`, zsh `noglob`, and bare `xargs` (only with no flags). NOT stripped: `command -v`, zsh `nocorrect`.
  - NOT stripped and therefore dangerous in a prefix rule: environment runners `direnv exec`, `devbox run`, `mise exec`, `npx`, `docker exec` — `Bash(devbox run *)` matches `devbox run rm -rf .`. Write one rule per inner command instead.
  - Always prompt, never auto-approved by a prefix rule: exec wrappers `watch`, `setsid`, `ionice`, `flock`, and `find` with `-exec`/`-delete`.
  - Leading assignments: an allow rule matches past only known-safe env assignments; a deny/ask rule matches past any (`Bash(rm *)` still catches `FOO=bar rm -rf tmp/`).
  - PowerShell: cmdlet aliases are canonicalized (`PowerShell(Get-ChildItem *)` also matches `gci`/`ls`/`dir`), matching is case-insensitive, and the AST is parsed so each subcommand is checked.
- `Read`/`Edit`: gitignore-anchored path patterns, NOT plain globs — `//abs` (filesystem root), `/anchored at the settings source`, `~/home`, bare/`./` (cwd). Bare filename matches any depth (`Read(.env)` == `Read(**/.env)`). Merged with sandbox filesystem rules.
  - `version >= 2.1.210:` file checks match ONLY `Edit(path)` and `Read(path)`. A `Write(path)`, `NotebookEdit(path)`, or `Glob(path)` rule is accepted but never matched, and warns at startup — use `Edit(...)` (covers every file-editing tool) and `Read(...)` (covers Grep/Glob) instead. A path-less tool-name rule such as a bare `Write` deny is unaffected.
  - `version >= 2.1.208:` a `Read` deny rule also blocks `Edit` on the same path, including creating a new file there. `Write`/`NotebookEdit` are not covered — add an `Edit` deny for paths no tool may change.
  - Single-segment relative dir patterns differ by rule type: `Edit(src/**)` as an ALLOW matches only `<cwd>/src`, but as a DENY/ASK matches a `src` directory at any depth. Every other shape (`/src/**`, `**/src/**`) matches identically in all rule types.
  - Symlinks: an allow rule needs BOTH the link path and its target to match; a deny rule fires when EITHER matches.
  - `/path` anchors at the rule's settings source: project → project root, local → original cwd, user → `~/.claude`, `--settings <file>` → that file's directory.
- `WebFetch(domain:host)`: matches URL hostname, case-insensitively, trailing `.` stripped from both sides; `*.example.com` = any subdomain at any depth (not the apex); `domain:*` == bare `WebFetch`. A wildcard in any other position matches only between two dots (`example.*` matches `example.org`, not `example.evil.com`).
- `Agent(AgentName)`: gate a subagent — `Agent(Explore)`, `Agent(Plan)`, `Agent(my-custom-agent)`; add to `deny` to disable.
- `Cd(<path-pattern>)`: gates the `/cd` command (not model-invocable); any `Cd` allow rule switches `/cd` to allowlist mode, a bare `Cd` deny disables `/cd` entirely, and deny checks every spelling of the target including each symlink hop. Anchors are shared with Read/Edit but matching is whole-path, not gitignore-style: `*` = exactly one segment, `**` = across segments, and a trailing `/**` also matches its named root.

| Mode                     | Protected-path writes (`.claude/`, `.git/`, etc.)                                                                                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Protected directories: `.git`, `.config/git`, `.vscode`, `.idea`, `.husky`, `.cargo`, `.devcontainer`, `.yarn`, `.mvn`, `.claude` (except `.claude/worktrees`).
Protected files: `.gitconfig`, `.gitmodules`; shell init (`.bashrc`, `.bash_profile`, `.bash_login`, `.bash_aliases`, `.bash_logout`, `.zshrc`, `.zprofile`, `.zshenv`, `.zlogin`, `.zlogout`, `.profile`, `.envrc`); package config (`.npmrc`, `.yarnrc`, `.yarnrc.yml`, `.pnp.cjs`, `.pnp.loader.mjs`, `.pnpmfile.cjs`, `bunfig.toml`, `.bunfig.toml`); `.bazelrc`, `.bazelversion`, `.bazeliskrc`; hook managers (`.pre-commit-config.yaml`, `lefthook.yml`, `lefthook.yaml`, `.lefthook.yml`, `.lefthook.yaml`); `gradle-wrapper.properties`, `maven-wrapper.properties`; `.devcontainer.json`; `.ripgreprc`, `pyrightconfig.json`; `.mcp.json`, `.claude.json`.

`permissions.allow` rules in settings do NOT pre-approve these writes; the check runs before allow rules are evaluated. In modes that prompt, a `.claude/` write offers **Yes, and allow Claude to edit its own settings for this session**, which covers later `.claude/` writes that session.

- `bypassPermissions`: only use in isolated environments (containers/VMs); refuses to start as root/sudo on Linux/macOS unless in a recognized sandbox. Admins block it via `permissions.disableBypassPermissionsMode: "disable"`. Enter only by starting with `--permission-mode bypassPermissions` / `--dangerously-skip-permissions`.
- `dontAsk` / `bypassPermissions`: Claude Code on the web ignores these as `defaultMode` from project/local settings. `defaultMode: "auto"` is also ignored from project/local settings (`version >= 2.1.142:`) — set in user/managed settings instead.

Pauses to prompting after 3 consecutive or 20 total blocks (not configurable; an allowed action resets only the consecutive counter). Subagent task descriptions are pre-checked `version >= 2.1.178:`. `version >= 2.1.199:` an MCP tool with `_meta["anthropic/requiresUserInteraction"]` skips the classifier and always prompts directly instead.
- Classifier inputs: user messages, tool calls, CLAUDE.md — tool RESULTS are stripped. It trusts the working dir and the remotes configured at session start; `version >= 2.1.200:` a remote added/repointed mid-session with `git remote add`/`set-url` is NOT trusted. Boundaries you state in conversation ("don't push") block matching actions but are re-read from the transcript, so compaction can lose them — use a deny rule for a hard guarantee.
- `version >= 2.1.210:` the classifier itself runs on Sonnet 5 by default (not your `/model`), falling back to the session's model when Sonnet 5 is unavailable or excluded by `availableModels`, or to an Opus model on a Fable 5 session. `version >= 2.1.198:` sandbox network verdicts are cached per host+port instead of re-checked per connection.

On providers with provider-specific IDs (Bedrock, Agent Platform, Foundry, Mantle) the upgrade is skipped instead.

### Effort levels

`low`/`medium`/`high`/`xhigh`/`max` (model-dependent; `xhigh` `version >= 2.1.111` as a capability). Set via `/effort`, `--effort`, `CLAUDE_CODE_EFFORT_LEVEL` (highest precedence), the `effortLevel` setting, or skill/subagent frontmatter `effort`. `low`/`medium`/`high`/`xhigh` persist; `max` and `ultracode` are session-only. `ultrathink` in a prompt requests deeper reasoning for that turn without changing the level.

- Support: Fable 5 / Opus 5 / Sonnet 5 / Opus 4.8 / Opus 4.7 take all five; Opus 4.6 and Sonnet 4.6 have no `xhigh`. An unsupported level falls back to the highest supported level at or below it. Default is `high` everywhere except Opus 4.7, which defaults to `xhigh`.
- `max` is session-only EXCEPT when set through `CLAUDE_CODE_EFFORT_LEVEL`. `auto` (env var only) resets to the model default.
- `ultracode` is a Claude Code setting, not a model level: it sends `xhigh` AND has Claude orchestrate dynamic workflows. Session-only; set via `/effort ultracode`, `--effort ultracode` (`version >= 2.1.203`), `--settings`/SDK `"ultracode": true`. Neither `effortLevel` nor `CLAUDE_CODE_EFFORT_LEVEL` accepts it, and a non-`xhigh` env value keeps workflow orchestration inactive. With workflows off it sets `xhigh` only.
- `version >= 2.1.195:` Enterprise admins can cap the max effort level per model per custom role (org config, not a settings key); levels above the cap are hidden from `/effort` and a higher request runs at the cap instead.

### Fallback chains

```json
{
  "fallbackModel": ["claude-sonnet-4-6", "claude-haiku-4-5"]
}
```

- Position carries meaning; the highest-precedence scope that defines `fallbackModel` supplies the entire chain. Capped at 3 models after dedup; `--fallback-model` flag overrides; `"default"` expands to the default model.
- Switch lasts the current turn only; only fires on overload/unavailable/non-retryable server errors — never auth/billing/rate-limit/request-size/transport errors, nor a denial by an org policy check.
- Elements outside `availableModels` or pointing at a retired model are dropped/skipped.
- `version >= 2.1.178:` the chain also covers compaction, but never falls back to a model with a SMALLER context window than the primary's; if every fallback is smaller, compaction surfaces the original error.
- Separate from content-based fallback (safety-classifier flags on Fable 5 and Opus 5): a biology-flagged Fable 5 request re-runs on Opus 5 and a cybersecurity-flagged one on Opus 4.8; on Opus 5, cybersecurity re-runs on Opus 4.8 while biology ends in a refusal (no fallback model). An excluded fallback target means refusal instead.
- `version >= 2.1.247:` the chain also covers subagents — a subagent whose request fails over tries the configured fallback models in order and continues on the one that accepts it, instead of ending the subagent (earlier versions ended it on such a failure); the parent session's model is unchanged.

### Merge behavior

- `availableModels` set only in user/project/local: arrays merge + dedup.
- `availableModels` (or `enforceAvailableModels`) set in managed/policy: replaces the merged result entirely; lower scopes cannot widen. `version >= 2.1.175:` this is the only way to enforce a strict allowlist (earlier versions merged the managed list). Admin-deployed managed sources do NOT merge with each other, so deploy the pair in the highest-precedence managed source — a list in a managed settings file is ignored once the admin console delivers any keys.
- `availableModels: []` blocks named selections but leaves the account-type Default usable, so `enforceAvailableModels` cannot lock users out of every model.
- `modelOverrides` maps Anthropic IDs → provider IDs; allowlist still matches the Anthropic ID, not the override value.
- Within the effective list, an entry naming a specific model in a family (a version prefix or full ID) disables that family's wildcard entry: `["sonnet", "claude-sonnet-4-5"]` allows only Sonnet 4.5, not every Sonnet model.
- All other model arrays follow the standard concatenate-and-deduplicate rule.

## Output styles

Output styles modify the system prompt to set role, tone, and output format. They do not change Claude's knowledge.

### Discovery

Output styles are markdown files loaded from:

- User: `~/.claude/output-styles/`
- Project: `.claude/output-styles/`
- Managed policy: `.claude/output-styles/` inside the managed settings directory
- Plugins: `output-styles/` inside the plugin directory

### Built-in styles

| Style       | Behavior                                                                                                                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default     | Built-in software-engineering system prompt                                                                                                                                                           |
| Proactive   | Executes immediately, makes reasonable assumptions, prefers action; stronger than auto mode and works without changing permission mode                                                                |
| Concise     | `version >= 2.1.237:` Leads with the result, skips preamble/narration, short by default; full detail on request; always keeps full error-report/security-warning/destructive-action-confirmation text |
| Explanatory | Adds educational "Insights" while doing software-engineering tasks                                                                                                                                    |
| Learning    | Collaborative learn-by-doing; adds `TODO(human)` markers for you to implement                                                                                                                         |

Project styles load from every `.claude/output-styles/` between cwd and repo root; `version >= 2.1.178:` on a name collision the directory closest to cwd wins.

### Frontmatter

| Field                      | Purpose                                                                                                                                 | Default   |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `name`                     | Style name if not the file name                                                                                                         | file name |
| `description`              | Shown in the `/config` picker                                                                                                           | none      |
| `keep-coding-instructions` | Keep built-in software-engineering instructions alongside the custom style                                                              | `false`   |
| `force-for-plugin`         | Plugin styles only: auto-apply whenever the plugin is enabled, overriding the user's `outputStyle`; first loaded wins if several set it | `false`   |

### Custom styles

- Create `<name>.md` in a discovery directory; Claude Code picks it up automatically.
- Custom styles add their instructions to the end of the system prompt and drop built-in software-engineering instructions unless `keep-coding-instructions: true`.
- All output styles (built-in and custom) trigger reminders to Claude to adhere to style instructions during the conversation.
- Output styles are **not** loaded from `--add-dir` directories (only the current working directory, parents, `~/.claude/`, and managed settings).
- Styles apply to the MAIN conversation only: a subagent runs its own system prompt, so a style never changes how it responds. A fork is the exception — it inherits the parent's full system prompt.

### Activate

Run `/config` → **Output style** (saved to `.claude/settings.local.json`), or set the `outputStyle` field directly. Applies after `/clear` or a new session (system prompt is read once at session start). The standalone `/output-style` command was deprecated v2.1.73 and removed v2.1.91.

## Statusline

A customizable bar at the bottom of Claude Code's interface. Configured via `statusLine` in settings.

### Configuration

```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 2
  }
}
```

| Field                  | Description                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `type`                 | Must be `"command"`                                                                                                            |
| `command`              | Shell command or path to script; runs on each status refresh                                                                   |
| `padding`              | Optional integer; horizontal padding around the output (default `0`)                                                           |
| `refreshInterval`      | Optional; re-run the command every N seconds (min `1`) on top of event-driven updates; use for time-based data or idle periods |
| `hideVimModeIndicator` | Optional boolean; suppress the built-in `-- INSERT --` text when the script renders `vim.mode` itself                          |

- Use `/statusline <description>` to have Claude Code generate a script and configure `statusLine` automatically.
- Script receives JSON on stdin; print one or more lines to stdout; each line becomes a row. Runs once at session start (including on resume), then after each assistant message, after `/compact`, on permission-mode change, on vim-mode toggle, and on each `refreshInterval` tick; debounced 300ms; in-flight execution cancelled on a new trigger.
- Forward slashes in `command` paths; `~` expands to home directory on all platforms.
- `version >= 2.1.153:` read terminal size from `COLUMNS`/`LINES` env vars (`tput cols` cannot read it).
- Requires workspace trust; disabled when `disableAllHooks: true`.
- Windows: Claude Code routes through Git Bash when available, PowerShell otherwise.

### `subagentStatusLine`

Same object shape (`type`/`command`); renders a custom row body per subagent in the agent panel. stdin = base hook fields + `columns` + a `tasks` array (each: `id`, `name`, `type`, `status`, `description`, `label`, `startTime`, `model`, `effort`, `contextWindowSize`, `tokenCount`, `tokenSamples`, `cwd`). `model` (resolved model ID) and `contextWindowSize` (that model's window in tokens) require `version >= 2.1.205` and are omitted for a task whose model isn't resolved yet. `effort` requires `version >= 2.1.214`, reports the configured value as written (an effort-level string or a numeric token budget — the applied effort may differ if the model lacks that level), and is absent when the subagent inherits the session level. Emit one JSON line per overridden row: `{"id":"<task id>","content":"<row body>"}`; omit `id` to keep default; empty `content` hides the row. Plugins can ship a default in their `settings.json`.

### Path prefixes (sandbox)

Paths in `filesystem.*` use standard conventions (NOT the `//` Read/Edit anchoring):

- Absolute paths: `/tmp/build`
- Home-relative: `~/.kube`
- `./` or no prefix: project root for project settings, but `~/.claude` for user settings.
- The older `//path` absolute form still works. If you used single-slash `/path` expecting project-relative resolution, switch to `./path`.
- Same prefixes apply to `credentials.files`.
- `version >= 2.1.224:` a trailing slash or trailing `/**` is stripped, so `~/build`, `~/build/`, and `~/build/**` are equivalent (earlier versions passed a trailing slash through, letting reads/writes under a `denyRead`/`denyWrite` path written with one slip past).
- Wildcard (`*`/`?`/`[`) support differs by list and platform: `allowWrite`/`denyWrite` support wildcards on macOS only — on Linux/WSL2 the sandbox mounts concrete paths, so a wildcarded entry (including one added from an `Edit` allow rule) is skipped with no effect; the `/sandbox` **Config** tab lists the `Edit` rules Claude Code skipped this way. `denyRead`/`allowRead` support wildcards on every platform.
