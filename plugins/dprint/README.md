# dprint

Skill /dprint:dprint with init (checks for a minimum dprint version, installs or updates dprint at user level after confirmation, offers to create a dprint config and to add dprint plugins for file types the project's dprint config does not cover), check [scope] and fmt [scope] (dprint check / dprint fmt on the current directory or a given path or glob; no argument runs fmt). Also formats every Write and Edit inside the working directory, and files changed there by other tools, with the project's dprint config via hooks when the working directory has a dprint config, and shows a toast when it has none (MCP server dprint-hooks; needs node and dprint >= 0.50 on PATH).

## Install

```text
/plugin install dprint@kwitsch-plugins
```

## Skills

| Skill    | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dprint` | Invoked as `/dprint:dprint [action] [scope]` (or bare `/dprint ...` where Claude Code resolves it). `init`: checks whether dprint is installed in at least the minimum version; if it is missing or too old, asks once via `AskUserQuestion` and, only on an explicit yes, installs it or updates it, then re-checks. With a usable dprint and no dprint config in the current directory it asks whether to create one (`dprint init -y`). It then scans the project's file types (`git ls-files`) and asks once per file type the dprint config does not cover whether to add a matching plugin; when several plugins fit, you pick one. `check [scope]`: runs `dprint check` (read-only). `fmt [scope]`: runs `dprint fmt`, which rewrites files in place. `scope` is one file, directory or glob relative to the current directory; without it the whole current directory is used. No argument = `fmt` on the whole current directory. When dprint or a project dprint config is missing, `check` and `fmt` run nothing and tell you to run `/dprint init` first. Renamed from `init-dprint` in 0.5.0 (`/dprint:init-dprint` -> `/dprint:dprint init`). |

## Hooks

| Event                                                       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PreToolUse `Write\|Edit`                                    | `format_pre` (MCP server `dprint-hooks`) formats the file with the project's own dprint config via `dprint lsp` before it lands on disk, only when the working directory or an ancestor has a dprint config and the file's real path is inside the working directory and not in the session scratchpad, and the file is not gitignored. Write: the whole content. Edit: only the edited lines (range formatting, whole-file fallback trimmed to the edit), returned as a small `old_string`/`new_string` edit. |
| PostToolUse `Write\|Edit`                                   | `file_written` remembers the content Write/Edit left in the file, so `file_changed` does not format it again.                                                                                                                                                                                                                                                                                                                                                                  |
| `FileChanged`                                               | `file_changed` formats a watched file inside the working directory on disk (whole file) after Bash or another tool changed it.                                                                                                                                                                                                                                                                                                                                                 |
| `SessionStart`, `CwdChanged`                                | Command hook `mcp/watch-paths.mjs` sets the FileChanged watch list to the files `dprint file-paths` reports for the working directory (`output-file-paths` on dprint 0.50-0.54).                                                                                                                                                                                                                                                                                               |
| Session start, `CwdChanged`, `EnterWorktree`/`ExitWorktree` | hooks module `hooks/notice.mjs` shows a 15 s toast when neither the working directory nor an ancestor (up to the git root) has a dprint config (needs a Claude Code build with function hooks).                                                                                                                                                                                                                                                                                |

## Notes

- Minimum dprint version: `0.50.0` (the `MIN_VERSION` constant in `src/skills/dprint/check-dprint.mts`).
- Installs via the official installer (`curl -fsSL https://dprint.dev/install.sh | sh`) to `~/.dprint/bin` — user level, no sudo. Updates use `dprint upgrade`.
- Shell rc files are never edited: if `~/.dprint/bin` is not on `PATH`, the skill prints the `export PATH=...` line to add yourself.
- Linux, macOS and WSL only. Requires `node` on `PATH`.
- The plugin list is `skills/dprint/dprint-plugins.json`, a snapshot of the plugins.dprint.dev registry (date in the file).
- Plugins are added with `dprint config add <name>`, which needs network access and resolves the latest version.
- A dprint config counts in the working directory or in the nearest ancestor directory that has one, but never above the git repository root, or inside a git worktree the worktree root (no global config). This is the format hook's own gate, not dprint's rule: once the gate is open, `dprint lsp` resolves the config per file itself and does not stop at the git root, so a config above the root applies to a started lsp but never opens the gate. The config names are `dprint.json`, `dprint.jsonc`, `.dprint.json`, `.dprint.jsonc`, `.config/dprint.json`, `.config/dprint.jsonc`. Plugins of `extends` configs and non-registry plugins (for example `exec`) are not recognized.
- check/fmt and `init` use the same config lookup (cwd or nearest ancestor, never above the git root); dprint's global config does not count.
- The scan needs `git`.
- The format hook needs dprint >= 0.50 (`dprint lsp`) on `PATH` or in `~/.dprint/bin` and `node` on `PATH`. Without a dprint config in the working directory or above (no `dprint lsp` is started then), without dprint, or on any error or timeout (30 s per request), the Write/Edit goes through unformatted.
- Which files are formatted is decided by dprint's config (plugins, includes, excludes); unmatched files are left alone.
- One `dprint lsp` process runs per working directory; `CwdChanged`, `EnterWorktree` and `ExitWorktree` hooks re-root the session/agent. Edits to CRLF files are formatted on the LF view Claude Code matches against; the file keeps its CRLF line endings. Formatting is scoped by real path: symlinks are resolved and dangling ones rejected, and the file's real path is inside the working directory and not in the session scratchpad (`scratchpad_dir`); without a known working directory nothing is formatted. Files under `node_modules`, `vendor`, `.git`, `.claude/worktrees`, `.claude/agent-memory`, and `*.local.*` files are never formatted.
- Files changed by Bash or other tools (FileChanged) are formatted whole on disk, unless their content equals the last Edit/Write result, they are gitignored, they are tracked and unchanged against the git index (`git status --porcelain` empty, for example after `git checkout`, `pull`, `reset` or `stash`), or they contain a lone CR. CRLF files keep their CRLF. At most 50 events are formatted at once (later ones are dropped), on a `dprint lsp` of their own, so a burst never delays a Write/Edit format. Limits: files created after session start or the last `cd` are not watched until the next one, EnterWorktree/ExitWorktree do not re-target the watch list, and with more than 5000 dprint files in the working directory FileChanged formatting is off.
- The first format in a project may download dprint plugins and time out; later calls succeed.
